## Interactive content

- [x] **In-browser Python playground (Pyodide) for ML snippets** — runs real Python 3 in the browser via [playground.html](playground.html). Curated snippets: linear regression on concrete strength, k-means on soil samples, decision-tree beam-safety classifier, NumPy traffic-flow stats, plus a welcome warm-up. NumPy, pandas, scikit-learn and matplotlib auto-load on demand; matplotlib `plt.show()` is captured to PNGs and rendered inline. Per-snippet edits persist in `localStorage`. <kbd>Ctrl</kbd>+<kbd>Enter</kbd> to run.
- [x] **Live engineering calculators** — [calculators.html](calculators.html) ships three browser-native, slider-driven estimators with instant recompute: (1) concrete-mix → predicted 28-day strength using Abrams' law + ACI 209 age factor + aggregate &amp; cement-type corrections (auto-classifies into M-grades); (2) Terzaghi/Vesći soil bearing capacity with shape factors and FoS; (3) beam-deflection ML estimator (closed-form elastic × cracked-section correction fit to 1 000 FEM beams, with IS 456 L/250 serviceability flag).
- [x] **Hyperparameter sliders + live loss curve** — new [lab.html](lab.html) ships two browser-trained models with real gradient descent: (1) polynomial regression on noisy 1-D data with sliders for degree, learning rate (log-scale), epochs, noise σ, dataset size and target curve; (2) a hand-rolled MLP classifier (real backprop, mini-batch SGD, BCE) with sliders for hidden units, hidden layers, learning rate, epochs, batch size, activation (ReLU / tanh / sigmoid) and dataset (moons / circles / XOR / spiral). Both panels render a live training-loss curve next to the model's prediction surface and surface diverging-LR warnings.
- [x] **Dataset explorer** — [explorer.html](explorer.html) lets you drop a CSV (or load a built-in synthetic concrete-strength sample) and instantly see: column stats table (mean / std / min / quartiles / max for numeric, unique / top value for categorical), a Pearson correlation heatmap (red = positive, blue = negative), an interactive scatter plot with X / Y / colour-by selectors, and a histogram grid for every numeric column. Pure JS, no libraries, no uploads — everything stays in the browser.
- [x] **Interactive confusion-matrix and ROC widgets** — [metrics.html](metrics.html) ships a live threshold slider that simultaneously updates a colour-tinted 2×2 confusion matrix, six core metrics (accuracy, precision, recall, specificity, F1, FPR) with traffic-light tones, an ROC curve with AUC and a marker dot tracking the current cut, a Precision–Recall curve with Average Precision plus a prevalence baseline, and a class-split score histogram with the threshold drawn over both populations. Five preset classifiers (strong, medium, weak, random, imbalanced rare-event) generated from seeded RNG, plus drop-in CSV upload (`y_true,y_score`). All maths and plotting are pure JS — no libraries, no uploads leave the browser.
- [x] **Side-by-side “traditional vs ML” demo** — [compare.html](compare.html) ships a real geotechnical comparison: predict V<sub>s30</sub> (the NEHRP site-class parameter) for any of **318 real Kathmandu-valley boreholes**. The left panel computes the closed-form NEHRP harmonic-mean formula on the measured V<sub>s</sub> profile; the right panel runs a linear-regression model trained live in the browser (80 / 20 split, closed-form normal equations with ridge stabilisation) on cheap inputs only — layer thickness, density, soil-type fractions, top-3 m density and density gradient — so it needs _no_ shear-wave survey. The page renders a coloured soil column with V<sub>s</sub> step-plot, both predictions with NEHRP site-class badges (A–E), the residual delta, a full-dataset scatter (train / test / current borehole) and live R² / RMSE / MAE on the hold-out. All data lives under [data/soil_profiles/](data/soil_profiles/) and is bundled by [tools/build_soil_dataset.ps1](tools/build_soil_dataset.ps1).

- [x] **Difficulty badges (Beginner / Intermediate / Advanced)** — auto-injected on every chapter hub by the `__diff_badges_init` IIFE in [js/sub-common.js](js/sub-common.js). ## Community / sharing

- [x] **Comments / discussion per sub-chapter (Giscus)** — `injectGiscus()` inside the new `__community_init` IIFE in [js/sub-common.js](js/sub-common.js) appends a `<section id="comments" class="giscus-block">` to every sub-page's `<main>`. Config lives in a single `COMMUNITY_CONFIG.giscus` object (repo, repoId, category, categoryId, mapping=`pathname`, theme=`dark_dimmed`, lazy loading). Until the maintainer enables the Giscus GitHub app and fills in `repoId`/`categoryId`, the block renders a dashed-border placeholder pointing to [giscus.app](https://giscus.app) instead of loading the script — so deploys stay clean.
- [x] **"Share this section" button** — same IIFE walks every `h2`/`h3` in `main.chapter-content` (skipping injected widgets), guarantees each has a slug `id`, and appends a `.share-anchor` icon button. Click copies `location.origin + pathname + #id` via `navigator.clipboard.writeText` (with a `<textarea>` fallback), updates the URL hash via `history.replaceState`, and shows a centred `.share-toast` ("Section link copied") that fades in/out. Buttons are visually hidden until the heading is hovered/focused; styles in [css/enhancements.css](css/enhancements.css).
- [x] **Feedback widget — "Was this helpful? 👍/👎"** — `injectFeedback()` in the same IIFE appends a `.feedback-widget` block (label + pill thumbs-up / thumbs-down buttons) above the comments. Vote is persisted per page under `ce-ai:fb:{pathname}` so the prior choice is restored, and a contextual message reveals a deep-link to `https://github.com/{owner}/{repo}/issues/new?...` with title, body (page URL + vote + template), and labels (`feedback,positive` or `feedback,needs-work`) pre-filled via `encodeURIComponent`. Owner/repo configured once at the top of the IIFE.

## Technical / SEO

- [x] **JSON-LD `LearningResource` schema on each sub-chapter** — new `__seo_init` IIFE at the bottom of [js/sub-common.js](js/sub-common.js) injects schema.org `LearningResource` markup on every `chapter{N}/subN.html` (with `name`, `description`, canonical `url`, `position`, `audience: Civil Engineers`, and `isPartOf` pointing at the home `Course`) and a `CollectionPage` on every chapter hub. Title/description are auto-read from `<title>` and `<meta name="description">` so the markup stays in sync with the page automatically. Idempotent — skips if a JSON-LD block of the same `@type` already exists.
- [x] **Per-chapter RSS / Atom feed** — new [tools/build-feeds.js](tools/build-feeds.js) reads `tools/chapters.json` and emits valid Atom 1.0 at [chapter1/feed.xml](chapter1/feed.xml) through [chapter6/feed.xml](chapter6/feed.xml) (62 entries total, each with title, canonical link, summary, tag-URI id, author). The same SEO IIFE also injects `<link rel="alternate" type="application/atom+xml">` into every chapter page's `<head>` for reader auto-discovery.
- [x] **Lighthouse CI in `tools/`** — [tools/lighthouserc.cjs](tools/lighthouserc.cjs) covers 8 representative URLs (home, chapter hubs, sub-page text/canvas variants, certificate, datasets, flashcards) with desktop preset, 2 runs/URL, perf/a11y/best-practices/SEO categories and category + audit budgets (perf ≥ 0.85, a11y ≥ 0.95, SEO ≥ 0.95, LCP ≤ 3.5 s, CLS ≤ 0.1, page weight ≤ 2.5 MB). [tools/run-lighthouse.ps1](tools/run-lighthouse.ps1) is a one-command local runner via `npx --yes @lhci/cli@latest autorun`; the config is drop-in for `treosh/lighthouse-ci-action` in GitHub Actions.
- [x] **Service worker for offline reading** — new [sw.js](sw.js) at the site root (registered by [js/theme.js](js/theme.js) which is loaded on every page) implements a versioned three-cache strategy: a static precache (root HTML, CSS, JS, manifest), network-first for HTML navigations (cached pages keep working offline with `/index.html` as the offline fallback), stale-while-revalidate for same-origin static assets, and cache-first for cross-origin Google Fonts / cdnjs. Old caches are evicted on `activate` via `CACHE_VERSION` bump.
- [x] **Auto-generated `sitemap.xml` from a single chapters JSON source of truth** — new [tools/chapters.json](tools/chapters.json) (seeded by [tools/bootstrap-chapters.js](tools/bootstrap-chapters.js) reading existing HTML) is the SoT; [tools/build-sitemap.js](tools/build-sitemap.js) regenerates [sitemap.xml](sitemap.xml) with 7 top-level pages + 6 chapter hubs + 62 sub-pages + 6 feed URLs in one shot. [tools/README.md](tools/README.md) documents the pipeline.
